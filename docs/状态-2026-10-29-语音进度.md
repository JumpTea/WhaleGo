## 1. 一句话

App 内：**打字 + 双脑 A/B + 语音朗读**可用；**语音输入不可用**，因为 WebView 拒绝麦克风。

## 3. 为什么 App 内不能说话（证据）

浏览器侧诊断（`~/.dsh/whalego/probe.log`）：

```
mic:start
mic:error NotAllowedError "Permission denied"   ← 56ms 后
recog:error not-allowed
```

同一份记录里 `isSecureContext: true`、`mediaDevices: true`、`SpeechRecognition: true`。

结论：API 都在，请求被 WebView **立即拒绝**，系统授权框从未出现。插件侧没有任何 API 能绕过。

对照：同一套页面在 Edge 里授权正常、`getUserMedia` 成功、页面宽度 430（App 内 394）。

## 4. 已实现（0.6.0）

- **双脑**：`auto` 简单只跑 A、复杂 A+B；`dual` / `voice` / `read` 可切
- **顺序**：A 生成结束才发 B，A 还在播时 B 已经在下边长
- **逐句**：`splitSpeakable` 切句，一句就绪即可合成；前端按播放揭示
- **打断**：`heard`（已播）与 `seen`（已见）落库，下一轮只注入听过的部分
- **设置**：语音页右上 ⚙，改模式/音色/语速/思考时球位置，走 `/whalego/prefs`
- **手势**：长按球切换思考时球位置；点空白收起；打字后自动缩球
- **filler**：预合成「我想想啊」，首句 400ms 没到就播
- **兜底转写**：录音 → WAV → `POST /whalego/transcribe` → 宿主 `speechToText`
- **诊断**：`probe.log` 记录 mic/识别/开关状态；⚙ 显示 `v0.6.0 · client 0.6.0`

## 6. App 补齐后的适配清单

接缝都在 `lib/nativeSeam.js`，逐项 `typeof bridge.x === 'function'` 探测，落地一个启用一个：

1. **麦克风**：WebView 实现 `onPermissionRequest` 后，`primeMic()` 会自动成功，录音兜底自动可用
2. **voiceLine**：把 `#generateVoice` 里的 `this.#seam.appendVoiceLine(...)` 打开即可（现在返回 false）
3. **voiceTurn**：`#runWebVoice` 的 A 分支改为走 `seam.openVoiceTurn`，B 继续用 `session.prompt`
4. **audioStream**：`#speak` 已有流式分支，`#canAttachAudio()` 为真即启用
5. **orb**：`#setStatus` 里的 `seam.setOrb` 已在调用，宿主实现即生效
6. **设置页**：`lib/index.js` 已导出 Cordis `Config`，App 只要渲染第三方 Config 即可

## 8. 浏览器入口（临时方案）

App 的 WebView 之外，用浏览器访问同一实例：

1. 先访问 `http://127.0.0.1:3099/`（本地小服务，给浏览器种登录 cookie）
2. 自动跳到 `http://127.0.0.1:3080/`，已登录
3. 进语音页 → 授权麦克风 → 点球录音，再点结束 → 本机转写

cookie 有效期 7 天；helper 是 `node /tmp/authserve.mjs`，重启手机后需重新启动。
