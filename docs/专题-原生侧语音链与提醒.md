## 3. 原生侧复刻：hostWrites lane

### 3.1 数据流

```
用户在 App 输入框发送（打字或系统语音输入）
  └─ session/event: user/message
      └─ engine.onUserMessage（守门：nativeAuto≠off、非 webMode、
         非自发送印记、非 /命令、非 voice-demo:、该会话无进行中回合）
          └─ engine.onSessionMessage → #newJob({hostWrites: true, stream: null})
              ├─ A 段：generateVoice（语音脑，逐句）
              │    └─ 语音行持久化（saveFile + session.append, App 原生渲染 + 内联播放）
              │    └─ 不自动播放（App 无播放完成回执无法回填 pending；按行内播放按钮重播）
              └─ B 段：**不跑** —— 会话 agent 正在跑的问题回合就是 B（job.hostWrites）。
```

### 3.2 为什么不重复跑文字脑

ask/read/explain 按钮路径里，插件的 textBrain 会把问题推进会话再拿来答案；按钮路径必须自己驱动。但用户消息路径上，宿主 agent **已经在答同一个问题**——插件再 prompt 一次就是「同一问题两抄答案」。所以该路径只补 A 段出声，B 段让宿主的回合完成。

## 5. 修正的不合理处

1. **自发送印记**：`#ownPrompt()` 在发起 textBrain prompt 前登记（sessionId+text 邮票），`onUserMessage` 看到同票直接跳过并清除——否则按钮路径的 prompt 回流会再次触发自动出声。
2. **`job.hostWrites` 分派**：`#runTurn` 优先分派 `#runVoiceRows`，只做 generateVoice → playVoice → finishJob；绝不写会话文字。
3. **TTS 失败不 stall**：hostWrites lane 内 `#playVoice` 抛错时记 warn 后照常 `finishJob`——该 lane 每张按钮都没有，卡住意味着会话被互斥锁挂起。
4. **`stream: null` 显式化**：hostWrites lane 不开 audioStream 也不走 media 自动播；`#deliver` 对空流直接返回。
5. **互斥与静默过滤**：同会话进行中回合直接跳过；`/` 命令、`voice-demo:`、空文本、agent 来源、`session/renamed` 等非 user/message 事件全部忽略。
